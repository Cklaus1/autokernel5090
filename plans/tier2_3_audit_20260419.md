### 7. ASI alt A+D priority scheduling at C=8 — **DEFER**

**Original verdict.** PARTIAL — C=4/16/32 pass; C=8 P99=4059ms (tail spike, priority didn't fire).

**Smoking-gun checks.**
- `bench_asi_alt_ad.py:67-73` uses a bare `asyncio.Semaphore(concurrency)` with fast launch — under `C=8` the two "long" lo-pri requests fill the queue head before the scheduler sees the hi-pri shorts, and `--scheduling-policy priority` + chunked prefill still cannot preempt mid-prefill on vLLM main.
- Remediation candidates: (a) `--num-scheduler-steps 1` (finer scheduling granularity), (b) `--max-num-batched-tokens 256` (tighter prefill chunks — currently 512), (c) per-request `--preemption-mode recompute` + raise priority threshold.
- Chunked-prefill at 512 tokens means a 4000-token long prompt occupies ~8 scheduling steps → priority check fires 8 times. Dropping to 256 doubles the preemption opportunities.

**Verdict: DEFER.** P(lands C=8 < 300 ms) ≈ 0.40. Real fix is LMCache (#6 above) with P99 *decode* (not prefill) path; priority scheduling has a ceiling here because prefill cannot actually be preempted once a chunk is in-flight on current vLLM.

### 11. Mega-graph v2 TC 1.30× KILL (m16n16k16 vs m16n8k16) — **DEFER**

**Original verdict.** KILL — 1.30× below 1.5× gate.

**Smoking-gun checks.**
- `kernels/csrc/mega_graph_gemma4_30layer_tc.cu:8,73-75` uses WMMA m16n16k16 (`wmma::fragment`). The PTX-level `mma.sync.aligned.m16n16k16.row.col.bf16` is what this compiles to on SM120.
- `mma.sync.m16n8k16` PTX uses *half* the N dimension (N=8 vs N=16) but issues in a tighter pattern; for M=1 decode workloads the effective N is wasted regardless (output row 0 is the only consumed row). Either shape loses ~15/16 of the M dim on every tile.
- The real bottleneck is M=1 decode: M=16 WMMA tile is 94% wasted. Switching m16n16k16 → m16n8k16 doesn't help this; it halves N throughput. Needs a fundamentally different M-expansion (batch 16 heads onto M via per-head layout) — which is essentially v5a's design.

**Verdict: DEFER.** m16n8k16 is a strictly-worse shape for this problem. The correct next experiment is M-dimension packing (16 heads into M), already explored in v5a/v5a1.

### 17. SWA sparse kernel 30% BW headroom — **RECOVER**

**Verdict: RECOVER, P(lands) ≈ 0.50.**

**Fix (~4 lines).** In `kernels/triton/swa_decode.py` around line 125-135, add `tl.multiple_of` hints and bump num_warps. Specifically line 340:

num_warps=8,  # was 4: Gemma4 GQA=2 wastes BLOCK_H rows; more warps amortize
